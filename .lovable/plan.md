# 修复 Match 空状态、投递时间轴黑点规则，并汇报进度

## 1. Match 页显示错乱（图 1、图 2）

已定位，不是数据问题，是样式作用域漏了：

`src/pages/Match.tsx` 里有两个返回分支。正常报告分支包在 `<div className="p-match">` 里，而「无报告」分支（第 166–199 行）直接返回 `bgDial + main`，**没有 `.p-match` 包裹**。因为迁移时所有 match 样式都加了 `.p-match` 命名空间前缀，这个分支就等于完全没有 CSS：背景表盘不再被限制成 1400px、`opacity .35`、`fill:none`，于是铺满屏幕变成图 1 的大黑圆；正文也退化成图 2 那样的裸文本。（已在本地用 690px 视口复现，DOM 里确认 `.p-match` 不存在。）

**为什么「明明传了简历和 JD 还是 No report」**：Match 的岗位来源顺序是 `?job=` → `?focus=` → 上次记忆 → 对比池第一个。投递页的「查看匹配」带了 `?focus=<岗位 id>`，所以永远能拿到报告；而岗位画像页解析完 JD 后只调用了 `setUI`，**从没把解析出的岗位写进岗位库/对比池**，跳转也是裸 `/match`。一旦对比池被清空，就没有任何 id 可取，落到空状态。

修复：

- 空状态分支同样包 `.p-match`，背景表盘恢复正常。
- 岗位画像页解析完成后，把该岗位写入岗位库并加入对比池，跳转改为 `/match?job=<id>`，让「上传 JD → 看匹配」这条链路自己成立。

## 2. 重新设计 Match 空状态

沿用 Swiss 风格，不引入新元素：

- 左栏：`01 · OVERVIEW` 标签 + 大字标题「还没有 / 岗位。」+ 一行说明。
- 右栏：把实心月相换成 0.5px 描边空心圆 + 虚线，中间 `AWAITING JD`，与「等待中」的语义一致，不再是一坨黑。
- 下方两个动作按钮改为主次分明：主按钮「上传 JD 建立岗位画像 →」，次按钮「从对比池选一个 →」。
- 窄屏（<900px）单列堆叠，背景表盘降到 `opacity .12`。

## 3. 投递时间轴：只有最新状态是黑色

现在 `src/pages/Delivery.tsx` 第 62 行判定为 `ACTIVE_ON.indexOf(ev.status) > -1 && a.status === ev.status`，写死了只有「已投递」「面试中」两种状态能点亮。所以切到「待投递」或「结束」时，新增的那条在时间轴上仍是灰的。

改为：每条投递记录的**最新一条事件**（时间最晚的那条）为黑色，其余一律灰色，与状态文字无关。删除 `ACTIVE_ON` 白名单。文字与圆点同时变黑（`.dot.on` 已有样式，不动 CSS）。
