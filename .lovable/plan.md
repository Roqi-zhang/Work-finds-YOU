# 能力花交互与岗位画像页 · 优化计划

只改下列 5 项，其余布局、文案、配色完全不动。

## 1. 去掉花瓣批注，改用描边深浅表达分数
- 删除花朵周围全部手写文字与手绘箭头（`#notes` 组、`drawNotes`、`.note-text` / `.note-line` 样式）。
- 分数改为编码在花瓣描边上：分数越高，描边越深越实；分数越低越淡。
  - 5 分 → 最深、线略粗；1 分 → 很淡、线最细；证据不足（null）→ 保留现有虚线小瓣，最淡。
  - 花瓣形状（长度随分数舒展）保持不变，仅叠加描边深浅这一层信息。
- hover 花瓣仍显示证据浮层（不变），hover 时描边加深为最强，作为唯一交互反馈。

## 2. 返回按钮的二次确认
- 仅当已建立画像（bloomed 状态，以及 analysing 进行中）时，点击左侧「← 返回」弹出确认弹窗。
- 弹窗为 Swiss Style 极简样式（0.5px 描边、无阴影、大写小字标题）：
  - 标题 `DISCARD PROFILE?`
  - 正文「返回将清空当前简历与已生成的能力花，是否继续？」
  - 按钮：`取消` / `确认返回`
- empty / ready 状态下点击返回仍直接 `history.back()`。

## 3. 简历卡片支持二次上传
- 简历卡片（ready 状态那张 CV 卡）整块可点击 → 打开文件选择器重新上传；拖拽到卡片上同样替换。
- 不新增任何显性按钮，仅加 hover 时卡片描边轻微加深的隐性提示。

## 4. bloomed 状态按钮组
- 主按钮文字「进入匹配 →」改为「下一步 →」，点击进入新的 JOB PROFILE 页。
- 主按钮左侧新增次级按钮「重新建立画像」（ghost 样式）：点击后清空结果、花朵回到占位态、状态回到 empty 并直接打开文件选择器，之后完整复用原有 上传 → 建立画像 → 开花 流程。
- 按钮下方提示文案保持不变、整体仍居中。

## 5. 新增 JOB PROFILE 页（第 2.5 页）
- 新文件 `public/previews/jobprofile.html`，由 profile.html 复制而来，排版、状态机、动效、花朵、分析卡片 100% 一致。
- 差异点：
  - 上传对象为岗位 JD（图片 / PDF / Word），文案对应改为「上传 JD」。
  - 左侧标题改为岗位版本。推荐用 **「解析岗位的<br/>理想能力花」**；备选：「生成这个岗位的<br/>能力花」「这个岗位<br/>在找什么样的人」。文档里仍保留「候选人画像」含义但表意更清楚。
  - 顶部导航与步骤条插入该页：01 Home / 02 Profile / **03 Job** / 04 Match / 05 Compare / 06 Delivery，Step 计数相应更新。
  - bloomed 后主按钮为「进入匹配 →」，跳转 `match.html`。
- 预览壳同步：`public/previews/index.html` 与 `src/pages/Index.tsx` 的页面列表新增「岗位」入口。

## 技术说明
- 描边深浅通过给每个 `.petal-g` 写 `style="--w: <score>"`，CSS 用 `stroke-opacity` + `stroke-width` 插值实现，不改花瓣生成算法。
- 二次确认弹窗与重建按钮均为纯前端静态原型逻辑，不接后端。
- 其他页面（home / match / compare / delivery）除导航新增一项外不做任何改动。
