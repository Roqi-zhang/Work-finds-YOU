# 岗位画像融合分析：能力包 + 联网资料融入原有分析，脚注溯源

## 1. 不再单独列「04 · 岗位能力依据」，直接融入原有岗位画像
- 去掉独立的 04 板块。生成岗位画像时，JD、岗位能力包和联网资料一起交给模型，一次产出**一份完整的岗位画像**。
- 原有 Key Points 和八个维度的 **ANALYSIS / EVIDENCE / [强度]** 格式完全不变，只是内容更完整：
  - ANALYSIS：以 JD 为主，结合能力包补全 JD 没写清楚的能力要点，以及行业里常见的考察重点。
  - EVIDENCE：除了 JD 原句，增加「有效证据」，即简历里怎样写才能证明这项能力。
  - 每句话按依据分层，并在句末标脚注 `[1]`：JD 明确要求 / 职责推导补全 / 行业与面经参考。
- 强度和评分权重仍然只由 JD 决定：补全内容可以帮助理解，但不会改变评分；面经永远不进入评分。
- 画像末尾新增独立板块 **「资料溯源 · Sources」**：按编号列出来源名称、平台、发布或采集日期、类型（JD 原文 / 通用标准 / 公司官方 / 社区面经）和链接，点击脚注可跳转到对应条目。
- 以前生成的岗位画像和匹配报告保持原样。新的融合画像会保存为新版本，所以历史分数仍可复现。
- 页面布局、按钮和跳转都不变。

## 2. 扩展检索来源（国内 + 国外）
检索来源分为几组，每组定向检索，结果统一注明平台：
- **国内社区 / 面经**：小红书、知乎、牛客网、脉脉、看准网、BOSS 直聘、拉勾、猎聘
- **国外社区 / 面经**：Glassdoor、Levels.fyi、Blind、Reddit、LinkedIn
- **搜索引擎通用检索**：Google（英文关键词）、百度（中文关键词）
- **标准与官方资料**：ESCO、O*NET、公司官网招聘页

规则不变：
- JD 仍是首要依据；社区和面经只作「情境参考」，不能成为硬门槛，也不参与评分。
- 只用岗位名称、职级、行业这类公开关键词检索，不会把 JD 原文或简历内容发给搜索服务。
- 小红书、脉脉等平台很多内容需要登录才能看。抓不到的会直接跳过，并在资料溯源里注明「该平台未取得公开内容」，不会编造。

## 费用说明
每次核对资料的检索量从约 4 条增加到 12–16 条，单次消耗的 Lovable credits 大约是原来的 3–4 倍（很少，按检索次数计费）。同一岗位的结果会继续缓存复用。

## 技术细节
- `_shared/role-sources.ts`：新增来源分组配置（平台名、域名、语言、类别）；按组构造 `site:` 查询，中英文各一组，并发执行，每组限 2–3 条；按 URL 去重；根据域名打上 `platform` 和 `sourceKind`（community / official / standard / search）标签；单组失败不影响整体。
- `_shared/role-policy.ts`：根据域名把社区来源判为 `interview_reference`，继续禁止它们进入正式评分锚点；补充测试。
- `role-knowledge` 输出：各项内容引用 `sourceIds`，前端据此生成编号脚注。
- `RoleKnowledge.tsx` / `JobProfile.tsx`：重写为 Key Points + 逐项 Analysis/Evidence 行 + 上标脚注 + 文末「资料溯源」列表，复用画像现有的样式。
- 验证：用 Product Designer JD 跑一次，确认至少有一个国内平台和一个国外平台的来源、脚注能跳转、格式与上方一致，并且边界测试通过。
