# 用户额度隔离 + 发布准备 + 运行说明文档

## 一、现状结论（已核对代码）

- **数据隔离：已经做到。** 所有业务表（岗位画像、个人画像、匹配报告、投递、对比池）都按 `auth.uid()` 做行级隔离，A 用户看不到 B 用户任何数据。
- **使用次数：目前没有真正生效。** 只有访客有限制（同一设备 1 次岗位解析，记在 `guest_trials`）。登录用户的计数表 `usage_counters` 建好了但**从未被读写**，也就是说现在注册后可以无限次使用，"注册送 3 次" 还没有实现。

## 二、要做的额度体系（沿用旧定稿）

| 档位 | 权益 |
| --- | --- |
| 访客（未登录） | 1 次岗位画像解析；不能上传简历、不能生成匹配报告 |
| 免费会员（注册） | 累计 3 次完整匹配报告，报告永久可查 |
| 付费档 | 页面占位展示，暂不开放收款 |

计费规则：
- 只在 `run-match` **成功返回时扣 1 次**；岗位解析、简历解析不单独扣次。
- 同一「岗位 + 简历」指纹命中缓存的报告**不重复扣次**（重复查看免费）。
- 额度在服务端校验（Edge Function 内先查用量再调模型），前端只做展示，绕不过去。
- 用完时返回明确错误码，前端弹出升级提示，而不是报 500。

实现要点：
- `run-match` 开头读 `usage_counters`（period 用 `lifetime`，免费额度是一次性 3 次），超额直接返回 402 + 文案。
- 成功写库后原子递增 `match_runs`。
- 顶部导航右侧显示「剩余 N 次」；额度耗尽时匹配按钮变为「升级」占位。
- 访客升级为注册用户时（已有的 claim 逻辑）不补送、也不惩罚，直接按新账号 3 次算。

## 三、发布 + 自有域名（腾讯云）

你需要提供 / 完成的：
1. 域名买好后告诉我**准确域名**（例：`example.com`），我在项目里连接并给出需要添加的 DNS 记录。
2. 在腾讯云 DNSPod 控制台添加两条 A 记录（`@` 和 `www`，值 `185.158.133.1`）+ 一条 TXT 验证记录（具体值连接时生成）。
3. 确定主域：建议 `www` 为主，根域 301 跳到 www。
4. 备案提示：`.com` 海外托管可以先跑通；若要在中国大陆正式对公众运营，需要 ICP 备案（要求域名在境内主体名下并解析到境内服务器），这一步不影响现在发布。

发布顺序：先补完额度校验 → 检查安全扫描 → 发布到 Lovable 域名 → 域名到手后连接自有域名。
