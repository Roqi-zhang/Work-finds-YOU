# MATCH 页：逐条证据折叠 + 04 改为「资料来源与分析思路」

页面结构、动效、顶部 78% 大字、月相盘、导航、CTA 全部保持不变。本次只做两件事：给 01/02/03 的每一条结论加一个可折叠的「依据」，并把 04 从「证据展开」改成模型的资料来源与推理记录。

## 01 一句话决策

四个字段（是否优先投 / 匹配分 / 胜算等级 / 投递优先级）每个下方新增一行细体触发器「依据 ↓」，点开显示该字段的判定依据：

- 判定依据：一句话说明这个结论从哪里来
- 引用来源：JD 第 N 条 / 简历第 N 段 / 画像维度分
- 置信度：高 / 中 / 低

另外 verdict 那句总结论下方也带一个「依据 ↓」，展示整体推理链的一句话摘要。

## 02 三个关键判断

优势 / 缺口 / 风险 三行，每行说明文字与花瓣标签之后新增「依据 ↓」，展开后展示：

- 我方证据：来自简历/画像的原文片段
- 岗位要求：来自 JD 的原文片段
- 推理：为什么这两者构成优势 / 缺口 / 风险
- 影响：对匹配分的加减分数

## 03 投前 3 步

三条行动项每条下方新增「依据 ↓」，展开后展示：

- 为什么要做这一步（对应哪个缺口 / 风险）
- 预期效果：匹配分变化、胜算等级变化
- 参考写法：一段可直接抄用的示例文案

## 04 分析资料来源与 AI 思路

原「证据展开」板块改名为「资料来源 · 分析思路」，仍默认折叠，展开后四块：

1. 资料来源：JD 原文、公司公开信息、同类岗位对照、画像快照（保留现有来源列表）
2. 分析步骤：模型分几步得出结论（解析 JD → 解析画像 → 维度对齐 → 打分 → 生成建议），逐步一行
3. 分项评分表：保留现有 8 维度评分条，作为打分过程的产物
4. 推理记录：占位区，后期直接承载模型返回的 reasoning trace（时间、步骤名、模型输出摘要）

原来的 CERIA 五段与「每个花瓣的推理」不再单列，其内容下沉到 01/02/03 的逐条折叠里。

## 交互与视觉

- 折叠触发器沿用现有 Swiss 风格：0.5px 上边线、10px 等宽全大写小字、右侧 ↓ 箭头旋转 180°。
- 展开使用与现有 `.ev-body` 相同的 max-height 过渡，不引入新动效。
- 同一区块内多个折叠可同时展开，互不影响。

## 技术说明

- 只改 `public/previews/match.html`，不动其他页面。
- 折叠逻辑改为一个通用委托：给所有 `[data-fold]` 触发器绑定一次点击事件，切换父元素 `open` 类，避免为每条写独立脚本。
- 每个折叠区用 `data-src-id` 标注它对应的结论 ID（如 `d.priority`、`j.gap`、`s.resume`），后期接入模型时按同一套 ID 把返回的 evidence 对象填进对应节点，前端结构不用再改。
- 内容仍为静态占位示例，字段命名对齐 PRD 的 `ApplicationDecision` / `StrategyPoint`，新增 `evidence: { basis, sources[], confidence }` 形状作为约定。
