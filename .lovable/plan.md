# 能力花重做：回滚 SVG 花，改为 1:1 参考图

范围：只改 `public/previews/profile.html` 的右侧舞台与左侧上传/按钮区。导航、下方 4 张画像卡片、跳转逻辑不动。

## 一、回滚

删除上一轮新增的全部 SVG 花逻辑：贝塞尔花瓣生成、花蕊、花茎叶、瓣尖标签、SVG 内批注、开花描边动效、花心上传圆。右侧舞台清空重来。

## 二、左侧

保持现状：标题、说明、步骤条、「← 返回」。左侧不放上传区。主按钮放在右侧舞台下方（见下）。

## 三、右侧舞台（上传区 + 花，同一块区域按状态切换）

舞台自上而下固定为三层：**主视觉区**（花 / 文件）→ **一行状态文字** → **一个主按钮**。三层位置和高度在所有状态下不变，只换内容，避免跳动。

**状态 1 · 未上传（empty）**

- 主视觉：完整展示参考图那朵单线条花（原图 1:1，不转 SVG，不裁剪变形，居中，最大高度约 520px）。
- 文字：`LET YOUR FLOWER BLOOM`
- 按钮：`上传简历`（点击选择文件；整个舞台同时支持拖拽上传，拖入时舞台描边由虚线变实线）。
- 无 hover、无 tooltip、无分数、无标签。

**状态 2 · 已上传（ready）—— 花立即被替换**

- 花以 0.4s 淡出并轻微下沉消失，同一位置换成一张「简历卡片」：Swiss 风格 0.5px 细线竖版卡片（A4 比例），卡片内用几道灰色细横线示意文本段落，顶部一行文件名（超长省略号）、底部一行 `PDF · 1.2 MB`，右上角小 `[R]` 标记。卡片淡入上浮。
- 卡片右下角一个极小的「×」可移除文件，移除后回到状态 1（花重新淡入）。
- 文字：`RESUME READY · WAITING TO BLOOM`
- 按钮：变为主按钮 `建立画像`。

**状态 3 · 分析中（analysing）**

- 点击「建立画像」后衔接原有加载动效：简历卡片内的细线由上至下逐行「被扫描」（一条细线自上而下扫过），同时卡片渐隐；花以低透明度自中心缓慢淡入并做极缓呼吸。
- 文字：`ANALYSING…` 配月相 loading。
- 按钮：进入 loading 态「分析中」并不可点击，约 2.6s 后完成。

**状态 4 · 完成（bloomed）**

- 花恢复实色完整呈现，手写批注在花的四周依次浮现（不改花本身形状）。
- 文字：`YOUR FLOWER HAS BLOOMED`
- 按钮：变为 `进入匹配`。
- 同时下方 4 张画像卡片（经验 / 技能 / 动机 / 风险）照旧渲染。


## 四、手写批注样式（参考图 1）

- 手写风字体栈（系统手写体 + cursive 回退），纯白/墨色单色，无底框。
- 每条批注 = 一行短文案（维度名 + 分数，如「执行交付 4/5」）+ 一根手绘感细弯箭头指向花的对应位置。
- 箭头为略带抖动的二次贝塞尔曲线 + 小箭头头部，0.5px 描边，画法与参考图一致（细、长、末端带钩）。
- 只标 3–4 条（最高分与差距最大的维度），其余维度留给下方卡片，避免画面拥挤。
- 批注绝对定位在花的容器上（左右各 2 条），不遮挡花本体。

## 五、花如何"因人而异"（方案评估）

参考图只作为**风格锚点**，不作为最终成品。三条路线：

**路线 A · 参数化手绘 SVG（推荐做主方案）**

- 用参考图的笔触特征（单线、0.5px、开口不闭合的有机曲线、微抖动、无填充）写一个花瓣生成器：输入 8 个维度分数 → 输出 8 片长度/宽度/弯曲度不同的花瓣路径，再叠一层随机抖动（种子 = 用户ID+岗位ID，保证同一份简历每次生成的花完全一致）。
- 优点：秒开、零成本、可 hover 交互、分数可反查、深浅色自适应、导出 SVG 清晰。这是产品里"每天都要看"的那朵花。
- 风险：上一版做丑过。这次做法不同——先用参考图逐段量出笔触参数（曲率、瓣长比、开口角、抖动幅度），把花瓣做成"一笔画不闭合"的形态，而不是对称椭圆。

**路线 B · AI 生图（做"成品海报"用）**

- 用 Lovable AI Gateway 的 `google/gemini-3-pro-image`（图生图/编辑），把参考图作为风格参考图 + 一句由分数拼出的 prompt（例：8 片花瓣，其中 2 片明显更长、1 片极短且线条虚断），生成一张与参考图同风格的独一花。
- 优点：笔触自然、像手绘、观感最好。
- 缺点：不可交互（是位图，没法 hover 花瓣）、分数与图形不精确对应（模型不会严格按 4/5 画长度）、每次约数秒且要花积分、同一简历重跑结果会漂。
- 所以它适合：分享卡 / 导出 / 报告封面，不适合作为工作台里的功能主体。

**路线 C · A + B 混合（最终建议）**

- 工作台内始终用 A 的 SVG 花（准确、可交互、免费）。
- 页面右上角加一个「生成手绘版」次级入口，调 B 出一张海报图，可下载/分享。
- 分析结束时的动效仍是 A 的开花描边动画，不依赖生图延迟。

**本轮范围**：预览阶段先做 A（用一组模拟分数驱动），B 留到接入真实 AI 分析时一起做（同一个 Edge Function 里，拿到结构化画像后再顺带请求一次生图）。参考图 `flower.jpg` 在 A 完成前先作为 empty 态占位。

## 技术说明

- 参考花图复制为 `public/previews/flower.jpg`，仅用于 empty 态占位（`<img>`）。原图为白底黑线：浅色模式用 `mix-blend-mode: multiply` 贴合米白背景；深色模式加 `filter: invert(1)`。
- bloomed 态的花为 JS 生成的 SVG：`petal(angle, score, seed)` 返回一条不闭合的贝塞尔路径，`stroke-width: 0.5`、`fill: none`、`stroke-linecap: round`；花心细蕊 + 一根花茎一片叶固定绘制。
- 抖动用确定性伪随机（seed 化的 `mulberry32`），保证同输入同输出。
- 批注层为覆盖在花上的绝对定位 SVG（仅画箭头）+ HTML 文本，坐标按花瓣角度算出，随容器缩放。
- 状态机：`empty` → `ready` → `analysing` → `bloomed`，用 stage 上的 class 切换。
- 后续接 B 时：Edge Function 内调 `https://ai.gateway.lovable.dev/v1/images/generations`，`model: google/gemini-3-pro-image`，`messages` 内带参考图 `image_url` + 分数 prompt，`stream: true`，图片存入 Cloud storage 并返回 URL。
