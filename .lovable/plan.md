# 可追溯的岗位能力包

## 目标与范围
面向互联网行业全部岗位，先建设产品与设计岗位的可靠能力包，再逐步扩展研发、数据、运营、市场等类别。保持现有页面布局、跳转、上传方式和扩展功能不变，只在岗位分析中增加能力依据与来源展示。

## 三层证据
1. **招聘方明确要求**：当前 JD 的原文、要求记录、引用位置是判断该职位要求的首要依据。外部资料不得改写招聘方明确要求，也不得把未提及的通用能力标为招聘硬门槛。
2. **岗位通用能力标准**：按岗位类别与职级组织能力、行为表现、有效证据及不应采用的推断。参考 O*NET、ESCO、行业标准和公开招聘资料，保留原始条目编号、链接、版本与引用位置。产品经理等岗位不能强行对应不匹配的国际职业分类；不能宣称获得机构认证。
3. **公司与面试情境资料**：整理公司官方资料、近期岗位信息、公开面经，标记公司、岗位、适用地区、资料日期和来源类型。面经只作准备参考，不作为公司正式录用标准；重复转载不视为多份独立证据。

## 第一版能力包
- 优先产品经理、AI 产品经理、UX/交互设计、UI/产品设计；使用初级、中级、高级的内部参考分级，不冒充外部机构的职级定义。
- 每项能力包括定义、可观察行为、不同水平表现、可接受的简历证据、对应八维能力及引用来源。
- 区分“外部资料明确支持”与“产品整理的映射/分级”；AI 草稿须审核后才成为发布版本。
- 未覆盖或资料不足的岗位继续使用现有 JD 分析，明确标记未匹配到已审核能力包，不能生成虚构标准或来源。

## 接入现有分析
- 保留 JD 与简历原文抽取过程，不将互联网内容混入原文证据。
- 根据岗位名称、职责、职级和适用范围选择能力包；无法可靠识别时不强行套用。
- 第一阶段以补充解释和参考建议接入：明确展示 JD 要求、通用能力与公司/面试参考，不让参考资料自动改变现有匹配分数、硬门槛或风险规则。
- 岗位与候选人的对照共用同一份已保存的岗位标准。候选人事实仍只由简历或用户补充经历证明；“未体现”不等于“不会”。
- 后续若将能力包中的行为锚点用于正式评级，另行版本化评价标准并重新生成对应画像、匹配结果，不默默重算旧报告。

## 追溯与展示
- 在现有岗位分析中增加一个可展开的能力依据区：能力包名称/版本、适用岗位/职级、三层来源、引用摘录和原文链接。
- 每条来源记录发布方、页面标题、链接、发布时间（未知则明确标记）、采集时间、引用位置、内容摘要及内容哈希。
- 来源冲突时保留差异说明，优先当前 JD；资料过期、无法获取、审核中均显示真实状态。
- 分析保存所使用的能力包版本与来源快照；资料更新生成新版本，已有报告和导出不自动换成新资料。

## 互联网资料获取
- 使用 Firecrawl 搜索与读取公开网页，仅搜索岗位、公司、职级等信息，不向搜索服务发送候选人简历、姓名或联系方式。
- 优先官方来源；不绕过登录、付费墙、访问限制，不收集面经作者个人信息。
- 搜索与读取会产生额外费用，接入时由连接卡选择授权方式。当前尚未连接该服务。
- 资料获取与 JD 分析分开执行、单独缓存；获取失败时保留正常画像，显示参考资料暂不可用，不编造引用。

## 技术实现
- 新增能力包、不可变发布版本、来源快照、岗位分析关联；使用 Lovable Cloud 加法式数据变更，不破坏已有数据。
- 管理操作由服务端验证现有管理员角色；普通用户只能读取已发布公共能力包和自己报告的关联来源，访客通过现有受控流程获取必要资料。私有 JD、简历不可进入公共能力包。
- 新增独立能力包解析/补充层，保留既有模型、评分公式、分析额度及媒体处理。参考元数据不放入现有评分标准哈希或无筛选的匹配提示中。
- 补充层缓存包含 JD 完整内容哈希、能力包版本/内容哈希、来源快照和解析版本；新生成及命中历史缓存的岗位均可获取相同来源信息。
- 精确来源以服务端实际取得的页面为准，模型只能引用允许的来源 ID；对无依据的引用、错误链接和招聘要求推断进行输出校验。

## 验收
- 每条能力和结论可回到 JD 原文或明确标记的参考来源。
- 外部标准不能新增招聘硬门槛，面经不能被当成正式录用条件，简历缺失证据不能被补造。
- 能力包更新不改变旧版本，不使参考资料暗中进入匹配评分；正常、历史缓存及未覆盖岗位路径都可用。
- 验证权限隔离、来源日期/链接、检索失败降级、候选人隐私保护，并跑通真实 JD → 岗位来源 → 简历对照 → 匹配报告 → 导出。
- 不修改首页、比较池、投递管理或扩展。
