# 能力花组件重做（仅画像页 profile.html 的花部分）

范围限定：只改能力花本体（SVG 花形、花瓣、批注、动效、状态）。左侧文案/步骤/上传区/按钮流程、下方 4 张画像卡片、导航与跳转逻辑全部不动。

## 我对文档的理解

**定位**：能力花是"双画像"的视觉语言——把企业胜任力模型转译成一朵能一眼看懂的花。候选人一朵、岗位一朵，横向并列，中间放一句匹配结论。不做叠加图、不做 dashboard、不用大面积颜色。

**8 个花瓣（固定维度）**，对应三类招聘判断：
- 能不能做：专业技能 / 业务理解 / 问题分析
- 能不能做成：执行交付 / 沟通表达 / 协作影响
- 能不能长期适配：学习适应 / 动机匹配

**花瓣编码规则**：
- 花瓣大小（长度）= 该能力强度，分数 0–5
- 证据不足 = 小花瓣或直接缺瓣，绝不记 0 分、不画满瓣
- 岗位瓣长 / 用户瓣短 = 需补强；用户瓣长 / 岗位瓣短 = 优势或过度匹配
- 无论分数如何，整体必须仍然是"一朵好看的花"（不能出现残缺到丑的形状）

**花瓣上只放三样东西**：能力关键词、分数、简短批注。批注用手写体、箭头指向花瓣、不超过 16 字、全图只标 2–4 条。更长的解释留给下方卡片。

**动效（开花）**：中心花心先出现 → 花瓣依次生长到各自分数长度 → 关键花瓣旁浮出手写批注 → 完成态。

**状态机**：empty（未上传，提示上传）/ loading（花瓣生长中）/ success / low_confidence（小瓣或缺瓣 + 证据不足标识）/ error（可重新生成）。

**交互**：花瓣 hover 或点击显示三件事——证据来源、为什么是这个分、对应的优化动作。

**移动端**：横向滚动，顺序为候选人花 → 岗位花 → 对比结论。

## 参考图取用点

单线条极简花：连续细线勾勒、花瓣是有机不对称的曲线（非几何椭圆）、大量留白、无填充、带一根花茎与一片叶。这正好对应 Swiss Style 的 0.5px 细线语言。

## 要改什么

当前 `public/previews/profile.html` 的花是 10 片规则椭圆 + 三层同心圆环，与参考图和文档都不一致。改为：

1. **维度 10 → 8**，改用文档定义的中文维度名（专业技能 / 业务理解 / 问题分析 / 执行交付 / 沟通表达 / 协作影响 / 学习适应 / 动机匹配）。
2. **花瓣形状**：改用贝塞尔路径生成的有机花瓣（参考图那种一笔画曲线），0.5px 描边、默认不填充；花瓣长度由分数驱动（`ry` 与路径控制点随 score 缩放），并加入微小随机偏移让每瓣不完全对称。
3. **花心**：中心保留上传圆，分析完成后花心画出细密的花蕊短线（参考图中心那组细线）。
4. **去掉三层同心圆环**，换成一条极淡的基准弧 + 一根花茎与叶（保持参考图的完整"花"意象）。
5. **分数展示**：改为 `4/5` 形式，标在瓣尖外侧。
6. **手写批注**：分析完成后，为分数最高/差距最大的 2–4 瓣渲染手写体批注（如"项目证据强"），用细线箭头指向对应花瓣。
7. **开花动效**：`stroke-dasharray` 描边生长 + 花瓣按序 stagger 展开，替换现有的整体 opacity 脉动。
8. **hover/点击**：花瓣悬停时该瓣描边加深并浮出小卡片，显示证据来源 / 得分理由 / 优化动作（预览阶段用示例文案）。
9. **状态**：empty（灰色轮廓虚线花，仅骨架）/ low_confidence（该瓣画成极小瓣并标"证据不足"）/ error（花瓣断线 + 重新生成入口）。

## 技术说明

- 仍是纯静态 HTML/CSS/JS，仅编辑 `public/previews/profile.html`；`_shared.css` 若需新增手写体与花瓣 token 会追加，不改已有值。
- 花瓣路径由 JS 按 `(angle, score)` 生成 SVG `path`，不写死 8 段路径，方便后续接真实数据。
- 手写体使用系统可用的手写风字体栈并加回退（预览环境不引入外部字体文件）。
- 分数保持 0–5 整数，`null` 表示证据不足，与后续 `AbilityPetal` 类型对齐。
