# 登录入口前移 + 导航顺序修正 + 试用计费规则

## 1. 岗位页登录入口（JD-First 后的第一道门）

现状：`JobProfile` 的提示行只显示「请先登录后再使用 AI 分析」纯文本，登录链接目前只做在 `Profile` 页（旧的 Resume-First 时代遗留）。

改动：
- 在岗位页的提示行加上与画像页一致的「去登录 →」链接（同样样式：下划线、灰字、跟在提示后）。
- 链接携带回跳参数：`/auth?next=/jobprofile`（画像页同理带上当前 `?job=` 参数）。
- `Auth` 页登录成功 / 已有会话时，读取 `next` 参数（校验为同源相对路径）回跳，而不是固定跳 `/`；邮箱注册的 `emailRedirectTo` 与 Google 登录的 `redirect_uri` 也带上该路径，保证三条路径都能回到原页面。
- 画像页保留现有登录入口不变，仅补上 `next`。

## 2. 导航顺序

按新的 JD-First 流程，顶部导航改为：

```text
01 HOME  02 JOB  03 PROFILE  04 MATCH  05 COMPARE  06 DELIVERY
```

只调整 `TopBar` 里的顺序与序号文案，路由路径与页面本身不动。

## 3. 商业模式与试用规则（本次一并确定，实现放在下一步）

流程变成「岗位画像 → 个人画像 → 匹配报告」，一次完整分析 = 3 次 AI 调用，所以额度按**「匹配报告」为单位**计，而不是按单页调用计，用户心智更清晰、也更贴合成本。

| 档位 | 条件 | 权益 |
| --- | --- | --- |
| 访客 | 未登录 | 1 次岗位画像解析（可看 JD 分析结果），**不能**上传简历、不能生成匹配报告 |
| 免费会员 | 注册登录 | 赠送 3 次完整匹配（岗位+简历+报告），报告永久可查，对比池上限 3 个岗位 |
| Lite ¥29/月 | 订阅 | 每月 30 次完整匹配，对比池 10 个，投递看板不限 |
| Pro ¥69/月 | 订阅 | 每月 120 次完整匹配，不限对比池，报告重跑（force）不额外计次 |

计费与防亏损规则：
- 计次时机：`run-match` 成功返回时扣 1 次；`parse-jd` / `parse-resume` 不单独扣次（但访客的 1 次岗位解析单独计）。
- 同一 `job + resume` 指纹命中缓存的报告不重复扣次；`force` 重跑在免费档扣次、Pro 档不扣。
- 额度在**服务端**校验（Edge Function 内查用量表后再调模型），前端只做展示，避免绕过。
- 冷启动期先只上「访客 1 次 + 免费 3 次」，付费档位先在页面上占位不开放收款，等留存数据出来再开。

## 技术细节

- `src/components/swiss/TopBar.tsx`：`NAV` 数组重排 + 序号文案。
- `src/pages/JobProfile.tsx`：提示行区域改为可容纳链接的 JSX（该页提示行目前由命令式 DOM 写入，需要把登录链接作为独立的 React 节点渲染在提示行旁，不改动现有 `hintLine.textContent` 逻辑）。
- `src/pages/Auth.tsx`：新增 `next` 搜索参数解析与白名单校验（必须以 `/` 开头、不以 `//` 开头），应用到已登录重定向、密码登录后跳转、`emailRedirectTo`、`signInWithOAuth` 的 `redirect_uri`（后者用 `origin + next`）。
- 计费规则本轮只落文档，不改数据库；实现时再新增用量表与服务端校验。

视觉与布局零改动。
