# 工作台文案与画像字段统一

## 1. 两侧说明文案重写（用户收益型）

替换 `JobProfile.tsx`（蓝框）与 `Profile.tsx`（绿框）花下方的一段说明文字，只改文案，不动结构。

岗位画像（蓝框）候选：
- A：上传 JD，看清这个岗位真正看重什么。8 项能力会按 JD 的强调程度长成花瓣，越舒展代表越关键；JD 没提到的只开虚线小瓣，不计分。
- B：把一份 JD 变成一张能力地图——哪几项是硬门槛、哪几项只是加分，一眼就能分辨，投递前不再靠猜。
- C：我们逐句读 JD，抽出可验证的要求并归入 8 项能力，越被反复强调的花瓣开得越大；未提及的保持虚线，不做臆测。

个人画像（绿框）候选：
- A：上传简历，看清你已经证明了什么。8 项能力会按简历中的实际证据长成花瓣，越舒展代表证据越充分；没有证据支撑的只开虚线小瓣，不计分。
- B：把简历翻译成能力证据——哪些能力你写清楚了，哪些只是提了一句没有佐证，一眼就知道该补什么。
- C：我们只依据简历原文取证，不替你脑补。有原文支撑的能力才开满瓣，证据不足的保持虚线，方便你有针对性地修改简历。

默认采用 A/A（收益开头、规则收尾，与现有句式长度接近），B、C 作为备选可随时替换。

## 2. 个人画像字段改为 Evidence + Analysis

现状：个人画像每个维度显示 `Evidence`（一句概述）、可折叠「依据明细」、`Why`、`Action` 四块；岗位画像只显示 `Evidence` / `Analysis` 两行。

调整（仅前端展示层，不改后端与数据结构）：
- Evidence 行改为承载「依据明细」的内容：按明细逐条列出（标签 · 角色、结论句、简历原文引用），让用户直接看到简历里哪句话体现了这项能力；无明细时回退到原来的 `evidence` 概述句，仍无则显示「简历中未见相关证据」。
- Analysis 行显示 `why`（标签由 `Why` 改为 `Analysis`），与岗位画像一致。
- 移除 `Action` 行与「依据明细」折叠按钮及其展开状态逻辑。
- 悬浮 tooltip 与导出内容同步为 Evidence / Analysis 两项，去掉 Action。
