# MATCH 页内容重构 · 对齐 PRD

依据 PRD 第 7 章（双画像能力花）与第 8 章（"投得更准"输出格式），MATCH 页应展示的内容如下。现有 `public/previews/match.html` 是 5 段横向滚动（78% match / 可迁移的工艺 / 三个空缺 / 下一步 / 就投它），结构方向对，但字段不完整、缺双花并列与证据层。

## PRD 规定 MATCH 页应有的模块

### 模块 0：双能力花并列（PRD 7.1.1）
- 左：候选人能力花；右：岗位能力花；中间一句简短匹配结论。
- 花瓣只显示：能力关键词 + 分数（如「专业技能 4/5」）。
- 只对最重要的 2–4 个花瓣加手写体批注，箭头指向花瓣，每条不超过 16 字。
- 差距大的花瓣用细线/箭头提示，不用大面积颜色、不用 dashboard 图表。

### 模块 1：一句话决策（PRD 8.1）
- 决策：优先投 / 改完再投 / 可投不优先 / 不建议投（`ApplicationDecision` 四值）。
- 匹配分（如 78）、胜算等级（win_probability）、投递优先级（如 Top 3）。

### 模块 2：三个关键判断
- 最大优势、最大缺口、最大风险，各一条。
- 每条标注关联花瓣（related_petals），可点击回跳到对应花瓣。

### 模块 3：投前 3 步
- 简历要改什么 / 作品集或项目表达要补什么 / 面试或自我介绍要准备什么。

### 模块 4：证据展开（默认折叠）
- 展开后按 Conclusion / Evidence / Reasoning / Impact / Action 五段展示。
- 另含分项评分表：8 个花瓣的 候选人分 vs 岗位要求分、证据强度、gap 等级。

展示优先级：默认只显示模块 0–3，模块 4 需点击展开。

## 8 个能力花瓣（PRD 7.4）
专业技能 / 业务理解 / 问题分析 / 执行交付 / 沟通表达 / 协作影响 / 学习适应 / 动机匹配。
评分 0–5：0 无证据，1 弱相关，2 基础满足，3 明确满足，4 强匹配，5 超出期待。

## 落地方式（本轮改 `public/previews/match.html`）

保留现有 5 屏横向滚动骨架和所有跳转入口（加入对比 / 直接投递 / 进入投递），只替换每屏内容：

```text
S1 双花并列 + 一句话决策（78 / 胜算 / 优先级 / 决策标签）
S2 三个关键判断（优势 / 缺口 / 风险，各带关联花瓣标记）
S3 8 维分项对照表（我的分 vs 岗位要求分，差距标记）
S4 投前 3 步（简历 / 作品集 / 面试）
S5 证据展开（CERIA 五段，默认折叠）+ 原有下一步按钮
```

视觉沿用现有 Swiss Style token：0.5px 细线、全大写小字标签、无彩色块；花瓣沿用 profile 页已确认的 10%–85% 透明度分级与描边逻辑。

## 不改动
- 不改导航、页面跳转逻辑与其他页面。
- 不接 AI，先用静态示例数据。
