# 手机号登录 + 拖拽上传 · 最小可行方案

## 一、手机号验证码登录（阿里云短信）

后端不自带国内短信通道，所以走「自建验证码 + 后端换取登录态」的最小闭环，手机号账号与现有邮箱账号各自独立。

### 流程

```text
用户输入手机号 → [send-sms-code] 生成6位码、存哈希、调阿里云发送
用户输入验证码 → [verify-sms-code] 校验 → 创建/查找用户 → 返回一次性登录令牌
前端用该令牌换取会话 → 登录完成，与邮箱登录后的体验一致
```

### 需要你提供的 4 个值（我会用密钥方式安全存储）

- 阿里云 AccessKey ID
- 阿里云 AccessKey Secret
- 短信签名（SMS 签名名称）
- 短信模板 ID（模板内容需含验证码变量）

### 改动清单

1. 新增表 `phone_otps`：手机号、验证码哈希、过期时间、尝试次数、是否已用。开启行级安全，仅后端函数可写，前端无直接读写权限。
2. 新增函数 `send-sms-code`：校验手机号格式（中国大陆 11 位），60 秒内不可重复发送、单号每天上限 10 条，调用阿里云短信接口。
3. 新增函数 `verify-sms-code`：校验验证码（5 分钟有效、最多 3 次尝试），通过后按手机号查找或创建用户，返回一次性登录链接令牌。
4. 登录页 `Auth.tsx` 增加「手机号」标签页：手机号输入 → 获取验证码（60 秒倒计时）→ 输入 6 位码 → 登录。样式沿用现有 Swiss Style（0.5px 下划线输入框、大写小字标签），不改现有邮箱/Google 入口。
5. 用户资料：手机号注册的用户在 `profiles` 里写入手机号作为显示名，额度逻辑（每天 20 次、开发者白名单）沿用现有实现，无需改动。

### 明确不做（保持最小）

- 不做手机号与邮箱账号的绑定合并
- 不做手机号 + 密码登录（只用验证码）
- 不做国际号码

## 二、拖拽上传

现状核查：个人画像与岗位画像两栏已经支持整块面板拖拽上传（`Profile.tsx` / `JobProfile.tsx` 已绑定拖放事件，CSS 已有 `.layout.dragging` 高亮态），这两处也是全站仅有的文件上传入口。

因此本项只做补齐与验收：

1. 岗位画像栏拖拽时的提示文案与个人画像统一为「松开即上传 · RELEASE TO UPLOAD」，松手后恢复原文案。
2. 拖入不支持的格式或超大文件时，沿用现有校验与错误提示，不新增样式。
3. 在工作台实际拖入 PDF / 图片 / Word 各一次做验证，确认两栏互不干扰、浏览器不会直接打开文件。

## 三、技术说明

- 短信调用在后端函数内完成，AccessKey 只存在于后端密钥中，前端不可见。
- 验证码只存哈希（加盐 SHA-256），不落明文；校验通过即置为已用。
- 登录态由后端签发的一次性令牌换取，前端不接触任何服务端密钥。
- 频率限制在数据库层按手机号统计，防刷短信费用。
