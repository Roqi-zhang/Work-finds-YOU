# 七项优化：画像分析深化 + 匹配报告可落地化

## 1. 岗位画像字段顺序对齐个人画像

岗位画像每个维度改为 **Analysis 在上、Evidence 在下**，与个人画像完全一致（工作台、快照页、导出、悬浮卡同步）。

## 2. 两侧 Analysis 的角色与深度升级

- **岗位画像**：模型扮演「熟悉各大公司用人标准的岗位专家」。每维 analysis 要说清：这个岗位需要什么能力，这个能力可以如何在简历中体现。篇幅从 80 字放宽到 120 字左右。
- **个人画像**：模型扮演「资深 HR」。严禁复述简历原句，必须从简历中提炼出**候选人体现了什么能力与特质**（如结构化思考、端到端推进力、跨职能协调）篇幅同样放宽。

## 3. 两侧新增 Key Points（核心点总结）

在「01 · CAN DO」上方新增一个 Key Points 区块，原有内容与格式完全不动，只是字体要加粗，目的是让用户一眼注意到，并且知道这个是重点：

- 岗位画像：这个岗位最看重的 3 项核心能力（每条一个短标题 + 一句话说明）。
- 个人画像：这份简历体现出的 3 项最突出能力（同样格式）。
两侧都是新增的一个总结分析步骤，随画像一起生成、缓存与快照。

## 4. Match 投前 3 步全面具体化（本次重点）

把三步固定为「简历 / 面试 / 作品集」，且要求模型输出可直接执行的内容：

- **简历**：结合 JD 的核心能力点给出 3 条针对性修改建议。每条格式为：小标题1: 要改什么，内容围绕着：一句话总结要改什么 → 小标题2:修改建议，内容围绕着：给出**可直接复制的改写文案/清晰具体的建议，告知用户如何改** → 小标题3:证据，内容围绕着：结合 JD 解释为什么这么改。
- **面试**：指名**哪一段经历**最值得准备、为什么、具体怎么准备（如：STAR 法则、需要理清的技术细节、要准备的解决问题实例等等，越具体越好，需要从面试官的角度思考整个岗位的面试官希望了解的内容），并附一条面试心态提醒。格式也是三段式
- **作品集**：仅当 JD 有作品集硬性要求时给出具体内容建议（例如重点放 UI 组件规范、还是交互流程与决策过程）；jd中无硬性要求时这一步不显示

## 5. 工作台两朵花缩小到 0.9

纯展示层缩放，交互、命中区域、动画逻辑不变。

## 6. Match「资料来源与分析思路」去掉推理记录

移除该区块中的「推理记录」列表（图 2 部分），其余来源 / 分析步骤 / 分项评分保留。

## 7. 优势、缺口、风险的依据改为两段

折叠依据从现在的四行（我方证据 / 岗位要求 / 推理 / 影响）精简为两段：

- **岗位要求**：JD 侧的原文依据
- **简历证据**：候选人侧的原文依据
让用户一眼看清结论由哪两侧材料对撞得出。

## 技术说明

- 后端提示词与 schema 改动集中在 `supabase/functions/parse-jd`、`parse-resume`、`run-match` 及 `_shared/schemas.ts`；新增 `key_points`（3 条）与更长的 `analysis` 字段，步骤对象增加结构化子字段（建议项数组、可复制文案、经历指名）。
- Key Points 存进已有的 `ideal_profile` / 候选人画像 JSONB 中，无需数据库迁移。
- prompt / schema 版本号一并递增，使旧缓存自动失效、下一次分析即生效。
- 前端改动：`JobProfile.tsx`、`Profile.tsx`、`Snapshot.tsx`、`Match.tsx` 与对应 CSS；导出内容同步新结构。
- 第 4 点会让匹配分析输出变长，耗时可能增加数秒，仍在现有超时预算内。
