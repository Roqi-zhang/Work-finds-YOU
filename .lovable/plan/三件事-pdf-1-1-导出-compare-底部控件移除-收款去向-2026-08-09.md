# 三件事：PDF 1:1 导出、Compare 底部控件移除、收款去向

## 1. PDF 导出改为「浏览器原生打印」

现在的做法是 html2canvas 把页面拍成一张位图，再切片塞进 jsPDF。位图路线天然做不到 1:1：字体会重排、CSS 变量/滤镜/SVG 会失真、分页只能靠猜。继续调参也只是在修一张截图。

最小且效果最好的方案：用浏览器自带的打印引擎输出 PDF。它用的就是渲染当前网页的同一套排版引擎，所以天生 1:1，文字还是可选中的矢量文字，分页由引擎按内容处理。

做法：

- 新增一份 `@media print` 打印样式（放进现有全局样式），只做必要处理：隐藏顶部导航、侧边进度条、导出按钮、背景装饰层；去掉每屏 `min-height:100vh`；展开所有折叠块；两栏网格改单栏；固定浅色配色（打印默认白底黑字）；花朵区块加 `break-inside: avoid`，章节标题加 `break-after: avoid`。
- 页面尺寸用 `@page { size: A4; margin: 14mm; }`，内容宽度由 A4 决定，天然居中、天然留边距。
- 导出菜单里的「PDF」改为：给 `<html>` 打上 `printing` 类 → 调 `window.print()` → 打印结束移除类。用户在系统打印对话框里选「另存为 PDF」。菜单文案改为「导出 PDF（打印）」，并在按钮下方给一行提示：目标选择「另存为 PDF」。
- 移除 PDF 分支里的 html2canvas + jsPDF 切片逻辑。PNG 导出保留现有 html2canvas 长图路径，Word 导出不动。

代价：多一步系统打印对话框（无法完全静默生成文件）。换来的是版式与网页完全一致、文字可搜索、体积更小。如果你更希望「点一下直接下载 .pdf 文件、不弹对话框」，那就只能回到位图路线，1:1 无法保证——这点需要你确认取舍。

## 2. Compare 页去掉底部控件条

删除 `Sort / Orbits / Density` 那一整行（`.controls` 区块）及其样式，纯展示层改动，轨道图、节点交互、右侧详情、查看匹配/投递/移出全部不变。

## 3. 付费收款去向

目前项目里**没有接任何支付**，所以现在用户即使想付费也没有入口，不会产生任何收款。额度系统只是免费次数计数。

要开始收款，需要在项目里启用支付集成（需 Pro 套餐）。届时钱的流向是：用户付款 → 支付服务商（Stripe / Paddle）→ 结算到你自己名下的收款账户（你的银行账户）。Lovable 不经手你的营收，你需要在启用流程里完成主体信息与账户验证。注意：中国大陆主体在 Stripe/Paddle 上开户有限制，如果目标是境内用户付费，这一步需要单独确认可行性。

是境内用户，需要支持微信和支付宝，请你看看有没有最简单方案

## 技术细节

- `src/components/swiss/ExportMenu.tsx`：PDF 分支改为 `window.print()`；删除 `PRINT_CSS` 注入 + jsPDF 切片；`printify` 仅保留给 PNG 用。
- 新增 `src/styles/print.css`（在 `main.tsx` 或 `index.css` 引入），承载 `@page` 与 `@media print` 规则。
- `src/pages/Compare.tsx`：删除 `.controls` 块；`src/styles/pages/compare.css`：删除对应规则。
- 依赖 `jspdf` 若无其它使用点则可从 package.json 移除。
