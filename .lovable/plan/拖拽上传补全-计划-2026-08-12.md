# 拖拽上传补全 · 计划

目标：所有「点选上传」的入口，同时支持把文件直接拖进去。交互逻辑与解析流程完全不变，仅扩大可拖放范围与视觉反馈。

## 现状

- 个人画像（Profile）与岗位画像（JobProfile）里，只有中间的花朵区域 `.visual` 绑定了拖放；简历/JD 卡片因为在花朵区域内部，属于顺带生效。
- 底部的「上传简历 / 上传 JD」按钮、按钮所在的整块左侧面板，以及重新上传的场景，拖拽文件过去不会触发上传，反而会被浏览器当成打开文件处理。
- 这两个页面是全站仅有的文件上传入口（投递管理页的新增投递只填文字，无文件）。

## 改动

1. 把拖放区域从花朵区扩大到整张画像卡片（Profile 与 JobProfile 各自的列容器）：拖入任意位置都能上传，包含底部上传按钮、简历卡片、空态占位区。
2. 拖拽悬停时给整张卡片加一个 Swiss Style 的高亮态：0.5px 描边由浅灰变为实线深色，提示文案切换为「松开即上传」，松手后恢复。不加阴影、不加色块。
3. 已有画像（ready / bloomed 状态）时拖入新文件，走与点击卡片重新上传完全相同的逻辑（含二次确认弹窗规则不变）。
4. 文件类型与大小校验复用现有 `handle()`，拖入不支持的格式时沿用当前的错误提示，不新增提示样式。
5. 工作台两栏并排时，各自只响应落在自己列内的拖放；窗口其它区域仍旧阻止浏览器默认打开文件的行为。

## 技术说明

- Profile.tsx：把现有 `onDragEnter/Over/Leave/Drop` 从 `.visual` 上移到该页的根容器，`dragging` state 不变，仅调整 class 挂载位置。
- JobProfile.tsx：同样把 `dragOn/dragOff/onDrop` 的监听目标从 `visual` 换成列根节点，卸载逻辑同步更新。
- profile.css / jobprofile.css：`.dragging` 样式选择器从 `.visual.dragging` 调整为卡片级，并补一条悬停时的提示文案样式。
- 不改任何上传、解析、额度或后端逻辑。
