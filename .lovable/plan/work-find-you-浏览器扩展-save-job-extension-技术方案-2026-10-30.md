# Work Find You 浏览器扩展（Save Job Extension）技术方案

## 目标
在任意招聘网站一键保存职位到 Work Find You 的投递管理（Job Tracker），之后可直接在站内分析 JD、做简历匹配。现有页面、交互、视觉完全不改，只新增扩展和一个接收入口。

## 用户流程
```text
浏览职位页 -> 点击扩展图标 -> 弹窗预填（岗位/公司/地点/薪资/链接/JD 正文）
-> 可修改 + 选择状态（待投递/已投递...）+ 备注 -> 保存
-> 出现在「投递管理」列表 -> 点击「分析 JD」进入 Workbench -> 匹配 -> Match
```

## 扩展本身（Chrome Manifest V3，兼容 Edge/Brave/Arc）
- **弹窗（Popup）**：Swiss 极简 + 手写体风格，与站点一致；未登录时显示「登录 Work Find You」按钮。
- **页面抓取（内容脚本，按需注入，只用 activeTab 权限）**，三层兜底：
  1. 结构化数据：页面中的 JobPosting（schema.org JSON-LD），LinkedIn、Indeed、许多公司官网都有。
  2. 站点适配器：首批 Boss 直聘、猎聘、拉勾、智联、LinkedIn、Indeed、Glassdoor 的选择器规则。
  3. 通用兜底：页面标题 + 用户选中的文字 / 正文最长文本块作为 JD。
- **右键菜单**：选中文本 → 「保存为 JD 到 Work Find You」。
- **去重**：同一链接已保存时提示「已在投递管理中」，可选择更新。

## 登录方式
扩展不单独做账号。用户在扩展里点「连接账号」→ 打开站内新页面 `/extension/connect`（已登录直接授权）→ 生成扩展专用令牌回传给扩展，存在扩展本地存储。可随时在站内撤销。游客不支持扩展保存（需登录）。

## 后端（新增，不改动现有表含义）
- 新表 **saved_jobs**：用户、岗位名、公司、地点、薪资、来源网站、原始链接、JD 正文、状态、备注、关联的岗位画像（可空）、创建/更新时间；按用户隔离，同一用户同一链接唯一。
- 新表 **extension_tokens**：仅存令牌哈希、名称、最近使用时间、是否撤销。
- 新云函数 **save-job**：校验令牌 → 清洗/截断字段 → upsert 到 saved_jobs → 写入投递记录（复用现有 applications 状态流，状态默认「待投递」）。限流：每用户每分钟 30 次。
- 新云函数 **extension-token**：签发 / 撤销令牌。
- 「分析 JD」复用现有 parse-jd（文本输入），沿用已有缓存与每日 20 次额度，不额外扣次数直到用户真正点击分析。

## 站内唯一的接入点
- 投递管理页读取新数据源，扩展保存的条目带一个小标记 [EXT] 和原链接；条目上提供「分析 JD」入口，跳到 Workbench 并预填 JD 文本。其他页面不动。
- 新增 `/extension/connect` 授权页和扩展下载/安装说明（解压 → chrome://extensions → 开发者模式 → 加载已解压）。

## 分阶段
1. **MVP**：扩展弹窗 + JSON-LD/通用抓取 + 令牌连接 + save-job + 投递管理展示。
2. **适配器**：国内外 7 个主流招聘站规则 + 右键菜单 + 去重更新。
3. **闭环**：一键「分析 JD → 匹配」，保存时可选择自动解析；后续上架 Chrome 应用商店。

## 技术细节
- 扩展源码放在项目 `extension/` 目录，打包成 zip 放 `public/` 供下载（预览环境用 fetch+blob 下载）。
- 权限：`activeTab`、`scripting`、`storage`、`contextMenus`；host 权限仅限本站云函数域名。
- 令牌：随机 32 字节，库中只存 SHA-256；请求头 `Authorization: Bearer`；云函数用服务端权限写库并强制 user_id 来自令牌。
- 安全：JD 正文上限 30k 字符，链接仅允许 http/https，去除 HTML 脚本。
- 测试：save-job 的令牌校验、去重、限流各一条 Deno 测试。
