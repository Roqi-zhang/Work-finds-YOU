# 六项修改：投递摘要、岗位花重建、跨页状态保留、对比池交互与分环

只改 `public/previews/` 下的 `delivery.html`、`jobprofile.html`、`profile.html`、`compare.html`、`match.html`，页面结构与视觉风格不变。动手前先各备份一份 `*.html.bak-0802b`，任何一项可整文件回滚。

所有状态一律走同一套本地存储层（`wfy.*` 键），读写集中在少量函数里，后期接真实数据时只替换这一层，跳转与交互逻辑不用再改。

## 1. 投递记录第二行只留匹配度

每条记录标题下的摘要行去掉状态文字（「投递」「初筛通过」等）与 `[W]/[I]` 标记，只保留「匹配 78%」。状态信息已由上方的状态下拉承担，不再重复。静态 5 条与从 Match 新建的记录用同一模板，编辑态与状态切换不再改写这一行。

## 2. 岗位画像页重建后花不完整

`jobprofile.html` 没有拿到画像页那次修复：`reset()` 与非动画绘制分支仍保留花瓣路径上的内联 `--len` 与 `animation-delay`，撤销动画后 dashoffset 回到满值，花瓣只剩残段。按 `profile.html` 已修好的写法，在重置与静态绘制时清除这两个内联属性，占位花恢复完整线稿。

## 3. 顶部导航切换页面时保留各页内容

现在每个页面是独立静态文件，切走再回来所有交互结果都归零。改为进入页面时自动恢复该页已有状态：

- 画像页 / 岗位画像页：记住当前状态（空 / 已上传 / 已开花）、文件名、8 维分数，回到页面时直接还原到 bloomed 视图，不重放开花动画。
- 匹配页：记住展开过的折叠项。
- 对比页：记住当前选中的岗位。
- 投递页：延续现有本地保存（状态、编辑内容、新增记录）。

导航链接本身不变，仍是普通跳转。

## 4. 「移出对比」二次确认

点击后弹出与画像页同款的 Swiss 极简确认弹窗（0.5px 描边、大写小字标题、取消 / 确认两个按钮），标题 `REMOVE FROM POOL?`，正文说明将把该岗位移出对比池。确认后从对比池数据中删除该岗位，轨道上的节点与右侧面板同步更新，并自动选中相邻的下一个岗位；池空时右侧显示空态提示。移除结果写入本地，刷新后保留。

## 5. 对比页「查看匹配 →」改为「投递 →」

按钮文案与行为改为投递：写入投递列表（状态默认「待投递」、日期为今天、带匹配分），然后跳转投递页并定位到这条新记录；同一岗位重复投递不重复添加。与 Match 页的「直接投递」共用同一写入函数。

## 6. 对比池按匹配度分环

节点所在轨道由匹配度决定，而不是写死的坐标：

- 内圈（r=140）：匹配度 ≥ 85%
- 中圈（r=220）：70% ≤ 匹配度 < 85%
- 外圈（r=290）：匹配度 < 70%

每个环内的岗位按匹配度从高到低沿圆周均匀分布，避免标签重叠；环内数量变化（新增或移出）时重新均分角度。新加入或删除岗位后立即按同一规则重排。

## 技术说明

- 本地存储键统一：`wfy.pool`（对比池）、`wfy.deliveries`（投递记录）、`wfy.focus`（跳转后定位）、`wfy.state.<page>`（各页 UI 状态）。所有读写包在 `readStore/writeStore` 两个函数中，接真实接口时只改这两处。
- 对比页的岗位数据源改为「静态种子 + 本地池」合并后的单一数组，节点位置全部由匹配度计算得出，删除后重新渲染，不再依赖硬编码的 `r/a` 字段——后期换成接口返回的岗位列表可直接套用。
- 确认弹窗从画像页抽出同一份结构与样式复制到对比页，不新增动效。
