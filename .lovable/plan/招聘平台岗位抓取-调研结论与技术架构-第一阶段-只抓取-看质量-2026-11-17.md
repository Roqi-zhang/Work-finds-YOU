# 招聘平台岗位抓取：调研结论与技术架构（第一阶段：只抓取、看质量）

## 一、GitHub 开源项目调研
| 项目 | 做法 | 能否直接复用 |
|---|---|---|
| BossHunter（1.2k 星） | 本机 Chrome 自动化，采集 BOSS/智联/51job/猎聘，AI 评分，人工确认投递；遇验证码自动停 | **不能商用**：许可证为 PolyForm 非商业，商用需作者书面授权。可参考思路 |
| jackwener/boss-cli（1k 星） | 读取本机浏览器 Cookie，调 BOSS 内部接口，含「推荐岗位」 | 未声明开源许可证，默认不可复制代码；接口为逆向，随时可能失效 |
| joohw/boss-cli | 本机 Chrome + CDP，面向 HR 端 | GPL-3.0，复用代码会要求我们整个产品开源 |
| auto-zhipin / job_hunter / job-hunter-web | Playwright 或 DrissionPage，在本机打开浏览器抓取 | BSD/MIT 可借鉴，但规模小、维护不稳定 |

**关键共同点：这些项目全部跑在用户自己的电脑上**，用用户本机已登录的浏览器。它们都不是“云端网站替用户登录”的架构，而且都提示有封号风险。所以不能原样搬进我们的网站，只能把它们的「抓取逻辑」移植到合适的位置。

## 二、为什么不能直接放在我们的网站后台跑
- 网站后台在云端，没有用户的登录状态；要替用户登录，就得保存用户的 BOSS/脉脉 Cookie。
- 云端服务器 IP 与用户常用设备不同，BOSS/脉脉会判定为异地登录，弹验证码或限制账号。
- 后台函数单次只能运行很短时间，跑不了完整浏览器。

## 三、推荐架构：浏览器扩展自动抓取（用户基本不用参与）
用户只需**一次性**操作：安装我们已有的扩展、在浏览器里正常登录过 BOSS/脉脉。之后：
- 每天 10:00 和 22:00，只要电脑开着、浏览器开着，扩展会**自己在后台**打开推荐页读取岗位，用户不需要点击，也看不到弹窗。
- 若那个时间电脑关着，下次打开浏览器时自动补跑一次。
- 如果平台弹出验证码或登录失效，扩展停止并在产品里提示用户，不尝试绕过。

```text
扩展定时（10:00 / 22:00）
  -> 后台读取 BOSS推荐、脉脉推荐（随后扩展猎聘/智联/51job）
  -> 移植开源项目的字段解析：岗位名、公司、薪资、城市、经验、学历、JD、原链接
  -> 上传到「抓取收件箱」，按 平台+岗位ID 去重
  -> 后续：规则初筛 + 现有匹配评分 -> 每天推荐 ≤10 个
```

备选（用户若希望电脑浏览器关着也能跑）：做一个本机小程序（类似 BossHunter），仍需电脑开机，安装门槛更高，不推荐首期做。
不推荐：云端保存 Cookie 代登录。

## 四、第一阶段范围（只验证抓取质量）
1. 扩展新增「推荐岗位自动采集」：先做 BOSS 直聘 + 脉脉；定时运行 + 「立即抓取」按钮用于测试。
2. 后台「抓取收件箱」保存原始字段，仅本人可见。
3. 每条标注字段完整度（如 JD 是否抓全）。
4. 一个仅自己可看的质量检查页：按平台看数量、完整度、重复率、原链接核对。
5. 不做：自动投递、自动打招呼、保存账号或 Cookie。

## 五、风险
- 自动读取可能违反平台用户协议，存在账号受限风险；控制低频、只读，并在产品中告知用户。
- 平台改版会让解析失效，用完整度监控及时发现。
- 只能在电脑浏览器运行，手机端无法做到。

## 技术细节
- 扩展：`chrome.alarms` 定时 + 启动补跑；`chrome.tabs.create({active:false})` 打开推荐页；优先读取页面已加载的内部接口响应，失败再解析 DOM（借鉴 boss-cli 字段结构，自行实现，不复制无许可或 GPL 代码）；每平台独立解析模块，随机间隔 3–8 秒，单次每平台 ≤30 条。
- 复用现有扩展的每用户可撤销令牌；新增 `ingest-jobs` 云函数批量写入。
- 新表 `scraped_jobs`（user_id、platform、platform_job_id 唯一、字段、completeness、fetched_at），RLS 仅本人可读。
