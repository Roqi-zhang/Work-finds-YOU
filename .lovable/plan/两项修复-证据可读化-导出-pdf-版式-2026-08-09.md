# 两项修复：证据可读化 + 导出 PDF 版式

## 1. 证据里的 r1 / e10 改成真实内容

现在「岗位要求」「简历证据」两行经常只写 `r1、r2、r3` 或 `e10、e11`，这些是内部证据编号，用户看不懂。

要做三层处理：

- **模型层（run-match 提示词）**：明确要求 judgements 的 `mine` / `required`、dimension_matches 的 `evidence` / `why`、steps items 的 `evidence`，一律写人能读懂的具体信息（简短引用 JD 原句 / 简历原句 + 关键数字），**禁止**输出 `r1`、`e10` 这类编号。
- **后端兜底（run-match 落库前）**：用 JD 证据表与简历证据表建立 `id → 原文` 映射，对上述文本做一次替换——凡出现 `r数字` / `e数字`，替换为对应原文摘录（超长则截断到约 40 字并加省略号）；找不到映射的编号直接删除，避免留下裸编号。
- **前端兜底（wfy.ts 适配层）**：已缓存的旧报告不会重跑，因此渲染时用报告里的 `evidence_links`（含 id 与 rawQuote）做同样的替换；仍无法解析的编号则隐去，该行为空时显示「—」。

结果：无论新报告还是历史报告，match 页展开的依据里都是可读的原句，不再出现字母编号。

## 2. 导出 PDF 版式：居中 + 完整花朵 + 合适边距

当前导出是把整页按屏幕宽度截图后切片，内容全部贴左，花朵被网格布局挤压/裁切。

调整 `ExportMenu` 的打印样式与切片逻辑：

- 克隆页面的打印 CSS 中，把主体内容容器限定为固定内容宽度并 `margin: 0 auto` 居中，左右留统一内边距；两栏网格（工作台/画像页）在导出时改为单栏堆叠，每块居中。
- 花朵区域（`.petal-stage` / `.flower-svg` 所在容器）在导出时取消 0.9 倍缩放与裁切限制，设为完整尺寸、水平居中、上下留白，确保整朵花完整出现在一页内（若一朵花高度超过可用页高，则按页高等比缩小）。
- 标题、章节块与花朵之间统一垂直间距，避免出现「上密下空」。
- jsPDF 侧：页边距由 24pt 提升到约 40pt；切片图按内容实际宽度水平居中放置，而不是从左边距贴齐。
- 分页保持现有「找空白行断开」的逻辑，另外禁止在花朵图块中间断页（把花朵块当作不可分割区域，遇到就整体推到下一页）。

涉及页面：match 页与岗位画像/个人画像页（它们共用同一个导出组件），两处都会同步生效。

- 需要重新部署 run-match 云函数。
