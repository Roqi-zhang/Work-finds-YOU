# 五项修复：花朵重置、Match 冗余按钮、状态流转、Delivery 操作区与状态下拉

只改 `public/previews/profile.html`、`public/previews/match.html`、`public/previews/compare.html`、`public/previews/delivery.html`，其他页面与所有跳转入口不变。

## 0. 回滚点

动手前先把这 4 个文件各复制一份为 `*.html.bak-0802`，任何一项不满意都能整文件还原。

## 1. 重新建立画像后花朵不完整

原因已定位：花瓣路径带 `.grow` 类，样式是 `stroke-dasharray: var(--len); stroke-dashoffset: var(--len)`。首次进入时 `--len` 未定义，属性无效，所以花完整显示；开花时脚本给每条路径写了内联 `--len` 并靠 `.blooming` 的 draw 动画把 dashoffset 收到 0。点「重新建立画像」时 `reset()` 只移除了 `blooming` 类，内联 `--len` 仍在，动画一撤销 dashoffset 又回到满值，于是花瓣只剩残段。

修复：`reset()` 里遍历所有花瓣路径，清掉内联的 `--len` 与 `animationDelay`（并在非动画的 `paint()` 分支里同样清除），让占位花恢复完整线稿。

## 2. Match 页底部重复按钮

删除页面最下方那组「加入对比 / 直接投递」按钮，只保留顶部 OVERVIEW 区那一组。

## 3. 加入对比 / 直接投递 的状态流转

Match 顶部两个按钮改为带动作的跳转（静态原型用浏览器本地存储串联，后期接真实数据此逻辑仍旧成立）：

- 「加入对比 →」：把当前岗位（公司、职位、匹配分等）写入本地的对比池，然后跳转 `compare.html`；对比页读取本地池，在原有对比项之外多渲染一条刚加入的岗位。
- 「直接投递 →」：把当前岗位写入本地的投递列表，标记状态「已投递」、日期为今天，然后跳转 `delivery.html`；投递页在日志最上方插入这条新记录，右侧时间轴同步加一个打点。
- 重复点击同一岗位不重复添加，只提示已存在。

## 4. Delivery 每条记录的操作区统一

每条记录底部统一为两个按钮：`查看匹配`、`编辑`。

- 查看匹配：跳转到该岗位对应的 match 页（原型阶段统一跳 `match.html`，并带上岗位标识参数，后期接真实数据可直接用）。
- 编辑：进入该条记录的编辑态，标题、状态行、正文、引用全部变为可直接输入的文本（contenteditable），按钮文案变「完成」；点完成退出编辑并把内容存到本地，刷新后保留。

## 5. 每条记录标题下方的投递状态下拉

在标题与摘要行之间加一个状态下拉，选项：待投递 / 已投递 / 面试中 / 结束。

- UI 沿用现有 Swiss 风格（0.5px 描边、10px 等宽全大写、无阴影、自定义箭头），不使用参考图的系统原生蓝色样式。
- 选择后立即更新该条记录摘要行的状态文字与右侧时间轴对应打点，并存入本地，刷新保留。
- 新从 Match 投递过来的记录默认选中「待投递」。

## 技术说明

- 全部为静态原型逻辑，不接后端；跨页数据用 `localStorage`（键如 `wfy.pool`、`wfy.deliveries`），后期换成真实接口时只替换读写层。
- Delivery 页现有 5 条静态记录保持不动，只在其上追加脚本增强（状态下拉、编辑态、按钮统一）；新记录用同一模板动态插入。
