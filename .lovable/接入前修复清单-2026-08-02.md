# 接入前修复清单 · 2026-08-02

审查范围：`public/previews/` 下 6 个静态页 + `src/pages/Index.tsx` 外壳。全部为只读检查，未改动任何代码。

## A. 必须先修（不修则真实数据一定出错）

### A1. 岗位 ID 三套并存
- `match.html:471` 写死 `JOB.id = "stripe-senior-frontend"`
- `compare.html:186` 用 `slug(公司+职位)` 现算
- `delivery.html` 5 条记录的 `data-id` 是手写字符串
三者靠「字符串碰巧相同」才串得起来。改公司名或职位大小写即失联。
**修法**：统一为后端主键 `job_profile_id`，所有跨页传递（pool / deliveries / focus）只传这个 id。

### A2. match 页不读岗位参数
`delivery.html:371` 生成 `./match.html?job=<id>`，但 match 页脚本从不解析 `location.search`，永远渲染 Stripe 78%。
**修法**：match 页以 `job_profile_id` 为入参拉取 `match_reports`，无参数时走「请先选择岗位」空态。

### A3. match 页内容 100% 硬编码，无数据插槽
01 决策四指标、02 三判断、03 投前 3 步、04 来源列表与 8 条评分条，全是写死的中文段落，只有部分带 `data-src-id`。
**修法**：先定义 `match_reports` 的 JSON 契约（decision / judgements[3] / steps[3] / evidence[] / dimension_scores[8] / sources[] / reasoning_trace），再把 HTML 改成按契约渲染的模板。这是接 AI 的前置条件。

### A4. 折叠状态用 DOM 索引记录
`match.html` 把展开过的折叠项存成 `folds: [0,3,7]`（`triggers` 数组下标）。内容一旦由数据动态生成，条目数变化，索引会错位到别的段落。
**修法**：改用稳定 key（`data-fold-id`）。

### A5. 对比池的「墓碑」机制会与后端冲突
`compare.html` 是 `SEED（12 条写死岗位） + wfy.pool - wfy.poolRemoved`。接后端后 SEED 必须整体删除，否则 12 条假岗位会永久出现且删了还会回来。
**修法**：池即 `compare_pool` 表查询结果，删除就是 DELETE，不需要 `poolRemoved`。

### A6. 投递记录被拆成三个存储 + 两套渲染路径
同一条记录的数据分散在 `wfy.deliveries`（新增记录）、`wfy.entryStatus`（状态+updatedAt）、`wfy.entryEdits`（编辑后的正文），而 5 条老记录只存在于 HTML 里、不在 `wfy.deliveries` 中。
**修法**：合并为单一 `applications` 记录模型，状态变更写 `application_events`，所有记录走同一个渲染函数。

### A7. 缺失空态（页面会塌）
- match：无报告时整页仍显示假数据
- delivery：无记录时 entries 与 timeline 都空白，右下统计仍显示 5/2/1
- profile / jobprofile：未建画像时靠占位花兜住，可接受
只有 compare 有池空提示。
**修法**：四个页面各补一个空态块。

### A8. 画像分析是假异步，没有失败态
`profile.html:546` 和 `jobprofile.html` 各写了一份硬编码 8 维 `result` 数组，`setTimeout 2600ms` 模拟分析。真实解析是长任务，会失败、会超时。
**修法**：状态机由 `empty / ready / analysing / bloomed` 扩为增加 `failed`（可重试）与 `queued`，分数来源改为接口返回。

### A9. 时间轴有孤儿条目与写死统计
`delivery.html` rail 中「Notion · archived」「Warp · declined」两条没有 `data-id`，不对应任何记录；`Avg match 77%` 与 `Cycle 28d` 是写死的。
**修法**：时间轴全部由 `application_events` 推导，统计实时计算。

### A10. 编辑态存 innerHTML
`delivery.html` 的 contenteditable 直接把 HTML 存进 `wfy.entryEdits`，落库后会成为脏 HTML / XSS 面。
**修法**：只取 `textContent`，按字段（title / body / quote）分别存。

### A11. 无登录态与用户隔离
所有数据是设备级 localStorage，换设备即丢、多账号会串。PRD 里「普通用户只能建 1 次画像」也无处拦截。
**修法**：接入登录后所有 `wfy.*` 业务数据迁到按 `auth.uid()` 隔离的表；未登录保留演示态，登录时一次性迁移。

### A12. 上传通道不存在
只有前端扩展名正则校验（`profile.html:441`），没有大小限制、没有真正的文件上传。
**修法**：接 Storage 上传 + 服务端类型/大小校验。

## B. 迁移到 React 时顺带修

- **B1** 6 个 HTML 各自复制了一份 `read/write` / `readStore/writeStore`，应收敛为单一数据层模块（后期只换这一处即可切接口）。
- **B2** 跳转全是 `location.href = "./x.html"`，迁移后统一换成路由。
- **B3** 日期格式散乱：`{day, mon, year}` 三字段、`"07·12"` 字符串、`updatedAt` 时间戳并存，应统一 ISO 字符串。
- **B4** `wfy.focus` 是一次性定位键，刷新即失效；改用 URL 参数（`?focus=`）更可复现。
- **B5** 主题键 `swiss-theme` 未纳入 `wfy.*` 命名；`_shared.css` 的 Token 需转成 CSS 变量 / Tailwind theme。
- **B6** 纯 UI 状态（`wfy.state.profile/jobprofile/match/compare`）迁移后应留在前端，不要进数据库——但 profile 的 `result` 字段属于业务数据，必须改由接口提供。
